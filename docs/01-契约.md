# 契约（精简版）

> **这份文件是唯一标准。** 代码和它对不上，改代码；要改它，四个人一起改一次，然后冻结。
> 目标：**一个够交作业的、简陋但完整可跑的四人协作项目**。界面不美化，功能不堆。

---

## 1. 我们做什么

单机桌面程序（Qt 6 Widgets + SQLite），四个功能块：

| # | 功能 | 归属 | 对应页面 |
|---|---|---|---|
| 1 | 商品上架 / 信息修改 / 下架 / 分类检索 | A | 商品检索、发布商品、我的商品 |
| 2 | 寄售登记（注册）/ 下单 / 订单记录 | B | 登录注册、我的订单、订单详情 |
| 3 | 交易状态跟踪 / 记录查询 | C | 交易记录 |
| 4 | 界面框架 / 数据库 / 导入 | D | 批量导入、主窗口 |

**只做 5 个页面**（主窗口左侧导航）：

```
商品检索    ← 默认页，A
我的商品    ← A
我的订单    ← B（顶部下拉：我买到的 / 我卖出的）
交易记录    ← C（全平台流水）
批量导入    ← D
```

另有三个对话框（不是页面）：**登录/注册**（B）、**发布商品**（A）、**订单详情**（B）。

### 明确不做（有人提就回答"契约里砍了"）

购物车、退款、评价、聊天、商品图片、用户头像、分类增删改、分页、导出 Excel/CSV、皮肤美化、多线程、客户端服务器、单元测试框架。

> **不做图片**：不用 `QFile::copy`、不用相对路径、不用 `QPixmap`，省掉一整类"换台电脑就裂图"的 bug。商品靠标题、分类、价格、成色、描述就能演示。

---

## 2. 五条铁律

1. **依赖只能单向**：`ui → services → data → core`。界面里不许出现 `SELECT`，`data/` 里不许出现 `QWidget`。
2. **改数据库只能走 `data/` 里的 DAO**，别的地方不许出现 SQL 字符串。
3. **每个文件只有一个负责人**（见 §5）。改别人的文件前先说话。
4. **写操作用 `OpResult`，不用异常**。
5. **每次写完跑一遍再提交**：能编译 + 能启动 + 自己那条流程能走通。

## 6. 公共类型

```cpp
// core/common/opresult.h
#pragma once
#include <QString>

struct OpResult {
    bool ok = false;
    QString message;     // 失败时给用户看的中文
    QString value;       // 成功时可选返回的 id / 订单号

    static OpResult success(QString v = {}) { return {true, {}, v}; }
    static OpResult fail(QString m)         { return {false, m, {}}; }
};
```

- 写操作 → `OpResult`
- 查单条 → `std::optional<T>`
- 查列表 → `QVector<T>`

实体（字段名和列名一致；末尾几个 `xxxName` 是 JOIN 出来给界面显示的，不存库）：

```cpp

// core/entity/product.h                     [A]
```

### 7.3 信号总线

**只在 `ui/mainwindow.cpp` 里 connect**，页面之间不许互相连：

```cpp
connect(m_auth,    &AuthService::loginSucceeded,  this, &MainWindow::onLoginChanged);
connect(m_auth,    &AuthService::logoutDone,      this, &MainWindow::onLoginChanged);
connect(m_product, &ProductService::productsChanged, this, &MainWindow::onDataChanged);
connect(m_order,   &OrderService::orderCreated,   this, &MainWindow::onOrderCreated);
connect(m_trade,   &TradeService::orderStatusChanged, this, &MainWindow::onDataChanged);
```

`onDataChanged()` 里就一句：让当前页重新查一次数据。**不做增量刷新**。

### 7.4 谁主导谁（老师问"有没有一个界面类主导其他类"就答这一节）

**有，就是 `MainWindow`（`ui/mainwindow.h`）。** 它是全项目唯一的"控制中心"，干三件事：

```
                 ┌──────────────── MainWindow（ui/mainwindow.cpp，D 独占）────────────────┐
                 │  ① 创建：new 4 个 DAO + 6 个 Service（buildServices()）                 │
                 │  ② 分发：把 Service 指针交给 5 个页面，页面自己不 new 任何东西           │
                 │  ③ 转发：页面之间不直接说话，一律经过 MainWindow 的信号槽                │
                 └───────┬──────────────────────┬──────────────────────┬─────────────────┘
                         │ new + 持有            │ 构造时注入指针        │ connect
                    data/*_dao            services/*_service        ui/pages/*
                         │                      │                      │
                    SQL / app.db         业务规则 / 事务          只画界面、只调 Service
```

规则三条（违反任何一条就是架构破了）：

1. **全项目只有 `buildServices()` 里出现 `new`**。页面、对话框一律不 `new` DAO 或 Service，只接收构造参数。
2. **页面之间零耦合**：`SearchPage` 不知道 `BuyDialog` 存在，它只 `emit buyRequested(int)`；由 `MainWindow::onBuyRequested()` 去开购买框，再把结果转给订单服务。
3. **跨页刷新只走 `MainWindow::onDataChanged()`**：谁改了数据，Service 发一个信号，`MainWindow` 收到后让所有页重查。页面之间不互发信号。

为什么这样设计（答辩话术）：

> "我们不把业务写进界面类。`MainWindow` 只做**组装和转发**（组合根 + 中介者），
> 业务规则在 `services/`，SQL 在 `data/`，界面只管显示。
> 好处是新加一个页面只要在 `buildServices()` 里接一根线，不用动任何已有页面。"

> ⚠️ 分工上的含义：`ui/mainwindow.*` 归 D 一个人写，别人**不要**在里面加代码。
> 你需要在主窗口里接自己的页面，就在 PR 里说明，让 D 加这三行（创建 / 分发 / connect）。

#### 7.4.1 "把功能类作为界面的成员"——这就是我们要的形式

老师说的"界面类调用其他类的函数，把功能类作为成员"，UML 里叫**组合（composition）**，
写成代码就是 `MainWindow` 里这一片（`D-详细施工步骤.md` 第 6 步有完整版）：

```cpp
class MainWindow : public QMainWindow {
    Q_OBJECT
public:
    explicit MainWindow(QWidget* parent = nullptr);
    ~MainWindow() override;
private:
    void buildServices();     // ① 唯一 new 的地方
    void buildPages();        // ② 把页面塞进 QStackedWidget
    void connectBus();        // ③ 唯一 connect 的地方

    // —— 数据层：四个 DAO ——
    IUserRepository*     m_userRepo    = nullptr;
    IProductRepository*  m_productRepo = nullptr;
    IOrderRepository*    m_orderRepo   = nullptr;
    ITradeLogRepository* m_logRepo     = nullptr;

    // —— 业务层：四个 Service（界面类调用它们，它们再去调 DAO）——
    AuthService*    m_authService    = nullptr;
    ProductService* m_productService = nullptr;
    OrderService*   m_orderService   = nullptr;
    TradeService*   m_tradeService   = nullptr;

    // —— 五个页面（主窗口的从属控件）——
    SearchPage*     m_searchPage     = nullptr;
    MyProductsPage* m_myProductsPage = nullptr;
    MyOrdersPage*   m_myOrdersPage   = nullptr;
    TradeLogPage*   m_tradeLogPage   = nullptr;
    ImportPage*     m_importPage     = nullptr;
};
```

调用链就是老师想要的那条，一层一层往下：

```
用户点按钮  →  页面（ui）  →  Service（业务规则/事务）  →  DAO（SQL）  →  SQLite
                  ↑ 全项目只有 MainWindow 创建这些对象并交给页面 ↑
```

**为什么用指针成员，而不是 `ProductService m_productService;` 值成员**（这条一定要会答）：

1. `Service` 是 `QObject` 的子类，`QObject` **禁止拷贝**（它的拷贝构造是 `= delete`），值成员写不出来；
2. DAO 要给 `Service` 和页面**共享同一个实例**，值成员会各拷一份，`new` 出来的指针才能"给谁都指向同一个对象"；
3. 用 `parent`（`new ProductDao(this)`）交给 Qt 的对象树管理，`MainWindow` 析构时自动删，不用手写 `delete`。

**页面也持有一个 Service 指针，算不算破坏"界面类主导"**：不算。UML 上的区别是——

| 关系 | 谁 | 写法 | 语义 |
|---|---|---|---|
| **组合** | `MainWindow` ◆—— `ProductService*` | `MainWindow` 里 `new`，`parent = this` | 我的，我负责创建和销毁 |
| **关联** | `SearchPage` ⇢ `ProductService*` | 构造函数参数传进来，**不 new、不 delete** | 借来用的，用完不管 |

新加一个页面时，`MainWindow` 只需三行：`new`、`stackedWidget->addWidget`、`connect`。**已有页面的代码一行都不用动**——这就是"主导"的实际收益，答辩可以直接拿这句当结论。

## 8. 状态机（C 的实现依据）

| 当前状态 | 动作 | 下一状态 | 谁可以做 |
|---|---|---|---|
| 待付款 | 付款 | 已付款 | 买家 |
| 待付款 | 取消 | 已取消 | 买家或卖家 |
| 已付款 | 发货 | 已发货 | 卖家 |
| 已付款 | 取消 | 已取消 | 卖家 |
| 已发货 | 确认收货 | 已完成 | 买家 |

其余组合一律非法。**C 必须穷举 5×4 = 20 组自检，合法数必须等于 5。**

```
待付款 --付款--> 已付款 --发货--> 已发货 --确认收货--> 已完成
   |               |
  取消            取消
   v               v
 已取消          已取消
```

已发货、已完成**不能取消**（取消要退钱，作业不做）。

## 9. 权限（没有角色字段）

权限靠**订单归属**推导：`order.buyer_id` / `order.seller_id` 和当前用户 id 比。

| 动作 | 允许的人 |
|---|---|
| 付款 / 确认收货 | `buyer_id == 当前用户` |
| 发货 | `seller_id == 当前用户` |
| 取消（待付款） | buyer 或 seller |
| 取消（已付款） | seller |

商品侧：**只能改 / 只能下架自己的商品**（`product.seller_id == 当前用户`）；**已售出的商品不能改信息、不能下架**；**不能买自己的商品**。
单机版只有一个登录态，切换用户 = 退出再登录。

> 为什么不要"角色"字段：角色是"人说自己是买家"，归属是"数据说这笔单是谁的"。后者不会自相矛盾。

## 10. 两处跨域事务（答辩就讲这个）

### 10.1 下单（B 编排，动 A 和 C 的表）

```
db.transaction()
  1. product = productRepo.findById(productId)        不存在 → rollback
  2. product.status != ON_SALE  → rollback "该商品已售出或已下架"
     product.sellerId == buyerId → rollback "不能买自己的商品"
  3. orderRepo.insert(order)                          ← B 的表
  4. productRepo.updateStatus(productId, ON_SALE, SOLD) ← A 的表（带条件）
  5. logRepo.insert(CREATE → PENDING_PAY)             ← C 的表
db.commit()
```

第 4 步的 SQL 是 `UPDATE products SET status=? WHERE id=? AND status=?`，并且检查
`q.numRowsAffected() == 1`。所以**连点两次购买只有一次成功**，第二次返回失败、整个事务回滚。

### 10.2 改状态（C 编排）

```
db.transaction()
  1. order = orderRepo.findById(orderId)
  2. 状态机校验 canTransit(order.status, action)
  3. 权限校验（§9）
  4. orderRepo.updateStatus(orderId, order.status, newStatus)  ← B 的表
  5. logRepo.insert(旧 → 新)                                   ← C 的表
  6. 仅"取消"时：productRepo.updateStatus(productId, SOLD, ON_SALE) ← A 的表
db.commit()
```

第 6 步就是"订单取消了，商品要回到货架"。不做步就变成"订单没了商品也卖不掉"。

## 11. 数据库访问规范

- 全局唯一连接：`QSqlDatabase DbManager::db()`，**只在主线程用**，不引 `QThread`。
- 打开时设 `PRAGMA foreign_keys = ON`。
- 查询三步：`QSqlQuery q(DbManager::db()); q.prepare(...); q.addBindValue(...); q.exec()`。
- 动态条件只拼**结构**，不拼值：

```cpp
QString sql = "SELECT * FROM products WHERE 1=1";
if (!q.keyword.isEmpty())    sql += " AND title LIKE ?";
if (q.priceMin >= 0)         sql += " AND price >= ?";
// 然后按同样顺序 addBindValue
```

- 排序不能拼用户输入，只能查白名单：

```cpp
static const QHash<QString,QString> orderMap = {
    {"time_desc","created_at DESC"}, {"price_asc","price ASC"}, {"price_desc","price DESC"}
};
sql += " ORDER BY " + orderMap.value(q.sortBy, "created_at DESC");
```

- 时间统一用 `QString`，`yyyy-MM-dd HH:mm:ss`，由 `datetime('now','localtime')` 生成。

## 12. CSV 批量导入（D）

Excel 里"另存为 → CSV"，不引任何第三方库。自己准备一个 `demo.csv`：

```
title,category,price,condition_level,description
九成新 iPhone 13,手机,3200,9,无划痕，电池健康 92%
高数教材 第七版,图书教材,25,7,有笔记
```

- `title` 必填 ≤60 字；`category` 按名字查分类（支持 `数码电子/手机` 这种"父/子"写法），查不到报错
- `price` 必须 > 0；`condition_level` 1~10，空则 9
- `description` 可空
- **卖家就是当前登录用户**（参数 `defaultSellerId`），文件里不写卖家列——少一列少一堆错

流程（**不做预览表格**）：

1. 选文件 → 读全部字节 → 先按 UTF-8 解码，有错误就按系统编码（中文 Windows = GBK）再解一次
2. 逐行校验，把每个问题记成 `"第 N 行 列名：原因"`
3. **只要有 1 行错，就一条都不导入**，把错误列表弹出来，用户改完文件再来
4. 全部合法 → 一个事务里插完 → 提交

> 不做"部分成功"，因为部分成功最难解释，也最难演示。

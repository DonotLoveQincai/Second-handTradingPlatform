# 02 · 环境搭建与协作手册

> 面向"基本没做过 Qt 项目"的同学。照着做，别跳步骤。
> 全部做完的标志：**你能在自己电脑上编译出这个程序，并且能把改动的代码推到 GitHub 上。**

---

## 1. 每台电脑都要装的三样东西

| 软件 | 版本 | 说明 |
|---|---|---|
| Visual Studio 2022（Community 即可） | 17.x | 安装时勾选「**使用 C++ 的桌面开发**」工作负载 |
| Qt | **6.11.2**，组件勾选 **MSVC 2022 64-bit** | 装到 `D:\Qt6`（和现有工程一致） |
| Qt VS Tools（VS 扩展） | 最新版 | VS 里：`扩展 → 管理扩展 → 联机` 搜 "Qt Visual Studio Tools" |

装完 Qt VS Tools 后要注册 Qt 版本：
`扩展 → Qt VS Tools → Qt Versions → Add`，
Name 填 `6.11.2`，Path 选 `D:\Qt6\6.11.2\msvc2022_64\bin\qmake.exe`，点 OK。

**四个人的 Qt 版本必须完全一致。** 版本不同 = 编译不过 = 白折腾一天。

### 验证环境（每人必做）

1. VS 里 `文件 → 打开 → 项目/解决方案`，选 `Second-handTradingPlatform/Second-handTradingPlatform.pro`
   （第一次会提示转换，点是，等它生成 `.sln`）
2. 右上角选 `Debug` + `x64`
3. `Ctrl+Shift+B` 生成 → 应该 0 错误
4. `F5` 运行 → 弹出一个空白窗口

**看到空白窗口，环境就通了。** 没通先看本文第 7 节。

## 2. 装 Git 并配置

1. 下载 Git for Windows：https://git-scm.com/download/win ，一路默认下一步
2. 打开 `Git Bash`（或 VS 里的终端），执行：

```bash
git config --global user.name  "你的名字拼音"
git config --global user.email "你的邮箱@example.com"
git config --global core.autocrlf false
```

> `core.autocrlf false` 很重要：Windows 上默认会把换行符改掉，导致每个人的文件都"有改动"，一提交就是全文件冲突。

**每个人必须用自己的 GitHub 账号提交**，不要四个人共用一个账号——否则答辩时无法证明谁写了什么。

---

## 3. 拿到代码（第一次）

仓库建好后，由 D 发给你链接。在你想放代码的目录（**不要放在 `C:\Program Files` 或桌面中文路径下**）：

```bash
cd /d/项目目录
git clone https://github.com/你们的账号/仓库名.git
cd 仓库名
git checkout develop
```

> **`clone` 之后必须再 `git checkout develop`。**
> `clone` 会把仓库里所有分支都拉到本地，但默认停在 `main` 上。日常开发都在 `develop`，忘了切就跟不上别人的代码。

然后：

```bash
git checkout -b feature/A-product      # A 用这个
# B 用 feature/B-order，C 用 feature/C-trade，D 用 feature/D-base
git push -u origin feature/A-product
```

以后每次开工，先确认自己在自己的分支上：

```bash
git branch          # 当前分支前面有 * 号
```

---

## 4. 每天的标准动作（背下来）

### 开工前

```bash
git checkout develop
git pull                            # 拿到别人的最新代码
git checkout feature/你的分支
git merge develop                   # 把别人的成果合进自己分支
```

> 每天先合 `develop`，可以**尽早**遇到冲突。冲突早遇到是小事，答辩前一天遇到是灾难。

### 收工前

```bash
git status                          # 看改了哪些文件
git add .                           # 全部暂存
git commit -m "feat(product): 完成上架校验"
git push
```

**提交信息必须带前缀**（`feat/fix/docs/test`），后面括号里是你负责的域。写清楚"做了什么"，不要写"改了一下"。

### 每周至少一次合并给别人

在 GitHub 网页上：
1. 点 `Pull requests → New pull request`
2. `base: develop` ← `compare: feature/你的分支`
3. 标题写清楚，点 `Create pull request`
4. 在右侧 `Reviewers` 里选**另一个同学**
5. 等对方点了 Approve，点 `Merge pull request`

**不要自己给自己合并。** 这一步就是"协作证据"，答辩时要展示。

## 5. 冲突了怎么办（别慌，很正常）

冲突的表现：`git merge develop` 后提示 `CONFLICT (content): Merge conflict in xxx.cpp`。

1. VS 里打开那个文件，会看到：

```cpp
<<<<<<< HEAD
    你写的代码
=======
    别人写的代码
>>>>>>> develop
```

2. **两个都保留、手工改成能一起工作的版本**，然后删掉 `<<<<<<<`、`=======`、`>>>>>>>` 这三行标记
3. 编译通过后：

```bash
git add 那个文件
git commit -m "merge: 解决 xxx.cpp 冲突"
git push
```

4. 如果是"两个人都新增了同一个函数的实现"这种，**先在群里说一声**，由负责那个文件的人来合并。

> 冲突基本都发生在四个人改同一个文件时。之所以契约里把文件归属写死（第 5 节），就是为了少出这种事。

## 6. 新增文件后必须做的事（90% 的"编译不到"是这里）

因为 `.pri` 用的是通配符 `$$files(...)`，**新增 `.cpp` / `.h` 之后，工程文件里还没有它**。

在 VS 里：

```
扩展 → Qt VS Tools → Open Qt Project File (.pro)
→ 选 Second-handTradingPlatform/Second-handTradingPlatform.pro
→ 等状态栏转完（几十秒）
→ 重新生成
```

判断标准：解决方案资源管理器里能看到你新建的文件了。

**每新增一个文件就做一次。** 忘了做，报错会是：

```
error C1083: 无法打开包括文件: "product_service.h": No such file or directory
```

或者链接时 `LNK2019: 无法解析的外部符号`。

## 7. 常见错误速查

| 现象 | 原因 | 解决 |
|---|---|---|
| `QSQLITE driver not loaded` | SQLite 插件没拷到 exe 目录 | 把 `D:\Qt6\6.11.2\msvc2022_64\plugins\sqldrivers\` 整个复制到 exe 所在目录，或跑一次 `windeployqt --debug/--release` |
| 编译通过但双击 exe / `F5` 毫无反应、无任何输出 | `debug\` 缺 `Qt6Sqld.dll`（用了 `QSqlDatabase` 之后必需），程序在加载 Qt 库时就没起来 | `windeployqt --debug --no-translations <debug 里的 exe>`；Release 用 `--release` |
| `C4828` 字符在当前源字符集中无效 / `C2001 常量中有换行符` | 源文件是 GBK（VS 在中文系统上新建文件默认就存 GBK），而 `.pro` 里开了 `/utf-8` | 仓库根有 `.editorconfig`（`charset = utf-8`），VS 打开后新建文件就是 UTF-8；老文件用 `文件 → 高级保存选项` → **UTF-8（无签名）** 存一次 |
| `C2039 "toVariant": 不是 "QVariant" 的成员` | 抄了不存在的写法，`QVariant` 没有 `toVariant()` | 改成 `.toString()` / `.toInt()` 等 |
| 中文变成乱码 `锟斤拷` | 源文件编码或没加 `/utf-8` | 文件另存为 UTF-8；`.pro` 里加 `QMAKE_CXXFLAGS += /utf-8` |
| `C1083 无法打开包括文件` | 新增文件后没重新生成工程 | 见第 6 节 |
| `LNK2019 无法解析的外部符号` | ①实现没写 ②文件没进工程（新增后没重新转换） ③进了工程但没重新生成 | 按这三条顺序查；最常见是没走 `Open Qt Project File (.pro)` |
| `LNK1120 N 个无法解析的外部命令` | `LNK2019` 的汇总行，解决掉 `LNK2019` 它自己就没了 | 同上，先看 `LNK2019` 指着哪个符号 |
| `vtable for XXX` 未定义 | 类里有 `Q_OBJECT` 但没被 moc | 该类的 `.h` 必须在 `.pri` 的 `HEADERS` 里（通配符会自动收，但要重新生成工程） |
| 运行时窗口一闪就退 | 数据库打开失败（本项目不用异常，`DbManager::init` 返回 false 要弹 `QMessageBox` 再退出） | 看 VS 输出窗口里 `DbManager::init` 传回来的错误文本 |
| `打开数据库失败` | `data` 目录不存在 | 启动时用 `QDir().mkpath()` 创建 |
| 程序改了但界面没变 | 没重新生成 / 跑的是旧的 exe | `Ctrl+Shift+B` 后 `F5` |
| `git push` 报 rejected | 远端有你没有的提交 | `git pull --rebase` 后再 push |
| `git push` 报 `Recv failure: Connection was reset` / `Connection timed out` | 网络到 GitHub 被中断，git 没走代理（国内常见） | 先确认代理软件端口（Clash Verge 7897 / Clash for Windows 7890 / v2rayN 10809），再 `git config --global http.proxy http://127.0.0.1:7897` 和 `https.proxy` 各设一次；代理关了要 `--unset` 撤销 |
| 提交后发现提交了 `debug/` 一堆东西 | `.gitignore` 被删了或不生效 | 把 `.gitignore` 恢复，`git rm -r --cached debug` |
| 新建的 `data/*.cpp`、`data.pri` 在 `git status` 里看不到、推送后队友拉下来缺文件 | `.gitignore` 里写了 `data/`，把源码目录 `Second-handTradingPlatform/data/` 也忽略了 | 改成带完整路径的 `/Second-handTradingPlatform/data/app.db`、`/Second-handTradingPlatform/data/images/`；自查 `git status --short -uall` |
| VS 里看不到 `.sln` | 还没转换过 | 打开 `.pro` 时选"是"进行转换 |
| Qt 版本下拉框是空的 | Qt VS Tools 没注册 Qt | 见第 1 节的 Qt Versions 步骤 |

## 8. 文件放在哪、数据在哪

- **数据库**：`exe所在目录/data/app.db`
  Debug 运行一般是 `Second-handTradingPlatform/debug/data/app.db`
- **想清空重来**：直接删 `data/app.db`，重启程序会自动重建（表结构在 `sql/001_init.sql` 里）
- **想恢复演示数据**：菜单 `工具 → 重置演示数据`（不用删库）

### 导入用的 CSV 长什么样

自己用记事本存一个 `demo.csv`（仓库里 `assets/demo/demo.csv` 也有一个现成的可以改），**第一行必须是表头**，用 Excel 另存为 CSV 也行：

```csv
title,category,price,condition_level,description
二手 iPhone 13,手机,3200,9,国行 128G 无划痕
高等数学 第七版,图书教材,25,7,有笔记
蓝牙耳机,耳机,150,8,音质正常
```

> 分类名必须和数据库里已有的分类一致（`数码电子 / 手机 / 电脑 / 耳机 / 图书教材 / 家居日用 / 服饰鞋包 / 运动户外`）。
> 记不住的话，程序导入失败时会把"分类 xxx 不存在"打出来。

答辩演示想换台机器：**把整个 `release` 目录拷到 U 盘**即可，数据库跟着走。

## 9. 四个人怎么配合（实操版）

| 时间 | 谁做什么 |
|---|---|
| 第 0 周周会 | D 讲契约，全员确认；每人认领自己的分支 |
| 每周一 20:00 | 30 分钟线上会：各自说"上周做了什么、这周做什么、卡在哪"，**D 记录到 `docs/meetings/日期.md`** |
| 每天 | 开工先 `merge develop`，收工 `commit + push` |
| 每周三、周六 | 提 PR，互相 review，合进 `develop` |
| 第 3 周 | 联调周，D 主持，四人一起坐到一台电脑前跑全流程 |
| 第 4 周 | 写文档、打包、演练答辩 |

### 卡住了怎么办

1. 先看本文第 7 节
2. 再看 `docs/01-契约.md` 对应章节
3. 还不行：**在群里发"我在做 X，报错是 Y，我试过 Z"**，别只说"我这跑不起来"
4. 30 分钟没解决就换人一起看，别一个人耗一晚上

## 10. 答辩要准备的"协作证据"清单

答辩前一周，四个人一起收集：

- [ ] GitHub 仓库的 **Insights → Contributors** 截图（显示四人提交数）
- [ ] **Insights → Network**（分支演进图）截图
- [ ] `Pull requests` 列表截图（显示 PR 数和 review 记录）
- [ ] `Issues` 列表截图（显示任务分配和关闭）
- [ ] `docs/meetings/` 里的周会记录（每次会议一份）
- [ ] 每人在自己电脑上打开 VS 的分支名截图
- [ ] 一次真实的冲突解决记录（`git log --merges`）

自查命令（答辩前一天跑）：

```bash
git shortlog -sne                  # 每人提交数
git log --oneline --all --graph    # 分支图
git log --author="你的名字" --oneline
```

如果四个人提交数差距悬殊（比如一个人 200 次、别人 5 次），说明分工没落实，答辩会被问穿。

## 11. 一条最容易踩的坑，单独说

**不要四个人共用一台电脑、一个 VS、一个 GitHub 账号。**

课程设计最常见的翻车方式就是这个：最后所有提交都在一个账号下，老师一看就知道是一个人做的，前面所有架构设计都白讲。

技术上要求：
- 每人一个 GitHub 账号
- 每人一个 `git config user.name`
- 每人在自己电脑上 `commit`（哪怕代码是讨论出来的）
- PR 必须是**别人** review

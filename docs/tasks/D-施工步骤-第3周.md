# D 的施工步骤 · 第 3~4 周（打包与收尾）

> 接在 [D-施工步骤-第2周.md](D-施工步骤-第2周.md) 后面。
> 前两周你做出的是“在你电脑上能跑的程序”。这几步要把它变成“在老师电脑上双击就能跑的程序”，并准备答辩。

## 这一阶段的三个目标

1. **Release 版能打包**：一个文件夹，拷到没装 Qt 的电脑上双击就开
2. **换机验证通过**：真正在别人的电脑上跑一遍，不是“应该行”
3. **答辩时有据可查**：Git 历史、PR 记录、会议记录、演示数据全部就位

顺序不能颠倒。**先打包，再换机，最后自检**。没在别人电脑上跑过就打勾“已完成”，答辩现场打不开是灾难。

## 第 13 步之前 · 先跑一遍联调用例

四个人的代码合到 `develop` 之后，界面上一个个点太慢，而且"点过了"不等于"都对"。仓库里有一份不依赖界面的联调用例 `tests/`，它把四个人的接口按验收清单全跑一遍，几分钟就能告诉你哪里对不上。

### 0.1 这份用例是什么

| 项 | 说明 |
|---|---|
| 位置 | `tests/integration_test.pro`、`tests/integration_test.cpp` |
| 依赖 | `QT += core sql`，**不带界面**，所以能在命令行里跑 |
| 数据 | 每次运行先删掉 exe 旁边的 `data/app.db`，从空库开始，跑完不影响演示数据 |
| 覆盖面 | 87 条断言，对应 15 个小节：建库、状态机自检、注册登录、分类、发布与校验、改价下架上架与越权、检索、下单三步事务、连点与自购、四个状态流转、取消释放商品、日志查询、CSV 导入、订单查询 |

### 0.2 怎么编译和运行

```bat
cd /d D:\你的路径\Second-handTradingPlatformDev\tests
call "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat"
D:\Qt6\6.11.2\msvc2022_64\bin\qmake.exe integration_test.pro -spec win32-msvc "CONFIG+=debug"
nmake
```

运行前把 Qt 的 `bin` 加进 PATH（否则会报找不到 `Qt6Cored.dll`）：

```bat
set PATH=D:\Qt6\6.11.2\msvc2022_64\bin;%PATH%
debug\integration_test.exe
```

输出长这样，最后一行是结论：

```text
PASS  7.3 商品被置为 SOLD（事务第 2 步）
PASS  7.4 订单表多了一条（事务第 1 步）
...
=====================================
PASS 87   FAIL 0
=====================================
```

有 `FAIL` 时会带一行 `[实际 ...]`，直接告诉你实际值是多少。返回码 `0` 表示全过。

### 0.3 这一次跑出来的真实结果

首轮 **PASS 78 / FAIL 9**。9 条里 **8 条是用例自己写错**（预期值和真实数据不符），**1 条是真 bug**：

| 失败项 | 原因 | 怎么处理 |
|---|---|---|
| `6.3 价格区间 1000~2000 有结果` | 用例里两件商品是 2999 和 2100，区间内本来就没有 | 改成 `2000~3100`，预期 2 件 |
| `11.3 按商品名关键字能查` | `TradeLogDao::search` 的关键字只匹配**订单号 / 备注 / 操作人**，不匹配商品名 | 用例改成按订单号查；顺带确认界面提示写的是"订单号 / 备注 / 操作人" |
| `12.x 两行合法数据全部导入` | 用例里写了 `手机 / 耳机`，但"耳机"的父类是**数码电子**，分类对不上 | 改成 `数码电子 / 耳机`，导入器没错 |
| `15.1 / 15.2 订单数 >= 4` | 用例只建了 3 单 | 改成 `== 3` |
| `2.1 用户名已被占用`、`6.5 我的商品 4 件` | 上一次运行的数据库没删干净（`DbManager` 用的是 `exe 目录/data/app.db`） | 用例开头按 `applicationDirPath()` 删库，不是当前工作目录 |
| `9.11 日志顺序` | **真 bug**：`TradeService::orderLogs` 走的是 `search()`（`l.id DESC`），订单详情的时间线是倒的 | 改成 `m_logRepo->findByOrderId(orderId)`（`l.id ASC`） |

修完之后 **PASS 87 / FAIL 0**。

### 0.4 记住三条

1. 用例失败先问"是用例写错还是代码写错"，别急着改代码——这次 9 条里 8 条是我自己写错的。
2. 用例里出现中文分类名，必须和 `sql/001_init.sql` 里的父子关系对得上。
3. 每次有人把自己的分支合进 `develop`，就重跑一遍。它是四个人之间唯一自动的"接口对不齐"报警器。

## 第 13 步 · 发布版打包

### 13.1 先理解 Debug 和 Release 的区别

| | Debug | Release |
| --- | --- | --- |
| 优化 | 关闭 | 开启，代码更快 |
| 调试信息 | 完整，能断点、看变量 | 基本没有 |
| `qDebug()` 输出 | 输出到 VS 的输出窗口 | 没有输出窗口可看 |
| 依赖的 Qt 库 | 带 `d` 后缀，如 `Qt6Cored.dll` | `Qt6Core.dll` |
| 体积 | 大 | 小 |
| 给谁用 | 你调试 | 交给老师 |

`#ifdef QT_DEBUG` 里的代码在 Release 版里**根本不编译**，所以 `dumpSchema()` 在 Release 里是空函数。这是对的，正式版不该往控制台打表名。

### 13.2 切到 Release 并编译

1. VS 顶部工具栏，把配置从 `Debug` 改成 `Release`，平台保持 `x64`
2. `Ctrl+Shift+B` 编译
3. 编译成功后 exe 在 `Second-handTradingPlatform\release\Second-handTradingPlatform.exe`

**先直接双击这个 exe 试一下，八成会报错**：

> 无法启动此程序，因为计算机中丢失 Qt6Core.dll。尝试重新安装该程序以解决此问题。

这是正常的。exe 只编进了你自己的代码，Qt 的库是运行时才去找的。你电脑上能找到是因为 VS 的调试环境配了 PATH，直接双击就没有那个 PATH 了。

### 13.3 用 `windeployqt` 把依赖拷过来

`windeployqt` 是 Qt 自带的工具，专门干这件事：读 exe，找出它依赖哪些 Qt 库、哪些插件，然后全部拷到 exe 旁边。

在 **Qt 命令行**或 git-bash 里执行（路径按你机器的实际位置）：

```bash
cd /d/DSH-workspace/Second-handTradingPlatformDev/Second-handTradingPlatform
/d/Qt6/6.11.2/msvc2022_64/bin/windeployqt.exe --release --no-translations \
    --compiler-runtime release/Second-handTradingPlatform.exe
```

**参数逐个解释**

| 参数 | 作用 |
| --- | --- |
| `--release` | 按 Release 版处理。不加的话它可能去找带 `d` 后缀的调试库，你机器上装了就能找到，结果拷了一堆调试 dll 给老师，老师电脑上跑不了 |
| `--no-translations` | 不拷 `translations/` 目录（几十 MB 的各国语言包）。你们界面全是中文硬编码，用不上 |
| `--compiler-runtime` | 把 MSVC 运行库（`vcruntime140.dll`、`msvcp140.dll` 等）一起拷上。不加的话，没装过 VS 的电脑会报“缺少 MSVCP140.dll” |
| `release/Second-handTradingPlatform.exe` | 要处理的 exe 路径 |

**它到底做了什么**

- 读 exe 的导入表，找出依赖的 Qt dll
- 把这些 dll 拷到 exe 同目录
- 拷贝 `plugins/` 下必要的插件子目录（**平台插件**、**数据库驱动**等）
- 生成一个 `qt.conf`，告诉 Qt 去当前目录找插件

### 13.3.1 ⚠️ `--compiler-runtime` 不一定真的拷了运行库

实际打这一版时发现：加了 `--compiler-runtime`，`release\` 里仍然**没有** `vcruntime140.dll`、`vcruntime140_1.dll`、`msvcp140.dll`。原因是你这台机器装了 VS，windeployqt 认为系统里已经有了就不拷；但老师的电脑上可能没有。

打完包先看一眼，缺了就手动补（这三个文件在 `C:\Windows\System32` 里）：

```powershell
$rel = 'D:\你的路径\Second-handTradingPlatformDev\Second-handTradingPlatform\release'
foreach ($d in 'vcruntime140.dll','vcruntime140_1.dll','msvcp140.dll') {
    if (-not (Test-Path (Join-Path $rel $d))) { Copy-Item "C:\Windows\System32\$d" $rel }
}
```

判断到底缺哪个，用 `dumpbin` 看 exe 的导入表，和自己目录里实际有的文件对一遍：

```bat
dumpbin /dependents release\Second-handTradingPlatform.exe
```

`Qt6Core.dll / Qt6Gui.dll / Qt6Widgets.dll / Qt6Sql.dll` 是 `windeployqt` 拷的；`VCRUNTIME140.dll`、`VCRUNTIME140_1.dll`、`MSVCP140.dll` 就得靠上面那一步。

补完**必须验一次**：把整个 `release` 文件夹拷到别的目录（模拟别人电脑），双击 exe，能出现登录窗口、并且同目录下自动生成了 `data\app.db`，才算依赖齐了。

### 13.4 逐项确认 `release/` 里有什么

打包完，`release/` 目录应该长这样：

```
release/
├── Second-handTradingPlatform.exe
├── Qt6Core.dll
├── Qt6Gui.dll
├── Qt6Widgets.dll
├── Qt6Sql.dll
├── platforms/
│   └── qwindows.dll
├── sqldrivers/
│   └── qsqlite.dll
├── styles/
├── imageformats/
├── vc_redist.x64.exe   （或 msvcp140.dll / vcruntime140.dll 等）
└── ...（其他 Qt 依赖）
```

| 文件/目录 | 缺了会怎样 |
| --- | --- |
| `Second-handTradingPlatform.exe` | — |
| `Qt6Core.dll`、`Qt6Gui.dll`、`Qt6Widgets.dll`、`Qt6Sql.dll` | 双击直接报“找不到 Qt6Core.dll” |
| `sqldrivers\qsqlite.dll` | **程序能开，但一点数据就报 “driver not loaded”**，库打不开 |
| `platforms\qwindows.dll` | 报 “could not find or load the Qt platform plugin windows”，程序根本起不来 |
| `vc_redist.x64.exe` 或 `msvcp140.dll` 等 | 报“缺少 MSVCP140.dll” |

**最容易漏的是 `sqldrivers`**。它缺失时程序能启动、界面能出来，但登录就失败。新手会以为是自己代码的 bug，查半天。看到 `driver not loaded` 第一反应就该是“`sqldrivers` 目录在不在”。

### 13.5 名字的含义

`windeployqt` 读作 “Windows deploy Qt”，`deploy` 是部署的意思，把程序从“开发机上的半成品”变成“别人能直接运行的东西”。

`--release` 里的 release 不是“发布”，在这里指“优化后的构建配置”，和 Debug 相对。

### 13.6 打包版第一次运行

双击 `release/Second-handTradingPlatform.exe`：

- 第一次运行会在 exe 同目录建 `data/app.db`（因为是 `applicationDirPath()`，不是相对路径）
- 登录要输入 alice / 123456
- 如果数据库是空的，用菜单 `工具 → 重置演示数据` 补上

**Release 版没有调试输出**，`qDebug()` 打了你也看不见。所以排错只能靠弹框和状态栏。这也是为什么第 4 步的 `DbManager::init` 要把错误信息拼详细：Release 版里那是你唯一的线索。

## 第 14 步 · 换台电脑验证（必须做）

这一步没有技术含量，但**跳过它的人答辩现场大概率翻车**。

### 14.1 拷什么

把**整个 `release/` 目录**拷到 U 盘。注意是目录，不是单个 exe。

要不要带上 `data/`：

| 情况 | 做法 |
| --- | --- |
| 想让对方看到已有数据 | 连 `data/` 一起拷 |
| 想给对方一个干净的程序 | 先删 `release/data/` 再拷，第一次运行自动新建空库 |

**答辩演示建议带数据**：现场重置演示数据要花几秒，而且万一忘了解释“为什么要重置”，不如直接带着摆好的数据。

### 14.2 找一台什么样的电脑

必须是**没装过 Qt、最好也没装过 VS** 的电脑。用室友那台只装了游戏和微信的机器最合适。

如果那台电脑装过 VS，`MSVCP140.dll` 可能已经有了，你就测不出 `--compiler-runtime` 到底有没有生效。**测试环境比开发环境干净，才能暴露问题。**

### 14.3 逐项验证清单

- [ ] 双击 exe，**能开**（不报缺 dll）
- [ ] 界面能正常显示，中文不乱码
- [ ] 能登录（alice / 123456）
- [ ] 能搜到商品（说明 `sqldrivers` 正常）
- [ ] 能下单（说明事务和三个 DAO 都正常）
- [ ] 能改订单状态，交易记录里能看到日志
- [ ] 能导入 CSV（在别人电脑上选文件，路径不同，测一下）
- [ ] 关掉重开，数据还在（说明 db 文件位置固定）

**任何一项失败，回到你自己电脑上修，然后重新打包、重新拷、重新测**。不要在别人电脑上改配置，那台电脑的状态你控制不了。

### 14.4 常见失败与原因

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 报缺 `Qt6Widgets.dll` | 打包时没带全 | 重跑 `windeployqt`，注意路径指向正确的 exe |
| 报 `driver not loaded` | `sqldrivers\qsqlite.dll` 不在 | 手动从 `D:\Qt6\6.11.2\msvc2022_64\plugins\sqldrivers\` 拷整个目录过去 |
| 报 “could not find or load the Qt platform plugin windows” | `platforms\qwindows.dll` 不在 | 同上，从 `plugins\platforms\` 拷 |
| 报缺 `MSVCP140.dll` | 没加 `--compiler-runtime` | 重跑并加上该参数 |
| 界面中文变方块 | 那台电脑缺中文字体 | 换 `Microsoft YaHei`，或把字体文件一起带 |
| 一点登录就崩 | 数据库文件损坏或权限不足 | 删 `release/data/` 重开；确认不在 `C:\Program Files` 下 |

## 附 · D 的常见坑速查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `C1083: 无法打开包括文件 "core/entity/product.h"` | `INCLUDEPATH` 没加，或新增文件没进工程 | `.pro` 里 `INCLUDEPATH += $$PWD`；`Qt VS Tools → Open Qt Project File (.pro)` 重新生成 |
| 新增 `.cpp` 后 `LNK2019` | 新文件没被收进工程 | 重新生成工程（`.pri` 通配符需要 qmake 重跑才生效） |
| 改了 `.ui` 界面没反应 | `ui_*.h` 是生成物，不是你改的那个文件 | 重新生成工程 |
| `vtable for XXX` 未定义 | 声明了 `Q_OBJECT` 但没被 moc 处理 | 确认头文件在 `HEADERS` 里（通配符会收），重新生成工程 |
| 中文乱码 | 源文件编码不是 UTF-8 | 全部另存为 **UTF-8 无 BOM**；`.pro` 里 `QMAKE_CXXFLAGS += /utf-8` |
| 数据库路径找不到 | 用了相对路径 | 一律 `QCoreApplication::applicationDirPath()` |
| 外键约束不生效 | `PRAGMA foreign_keys` 是**按连接**生效的 | 每个新打开的连接都要执行一次 |
| 点“交易记录”出来“我的订单” | `addWidget` 和 `addItem` 顺序不一致 | 两边顺序改成完全一样 |
| 信号发了界面没反应 | 槽没连上 / 连错了对象 | 在发射处和槽里各打一行 `qDebug()` 定位 |
| 改了代码但运行的是旧程序 | 编译没成功，跑的是上次的 exe | 看输出窗口有没有 `生成: 成功 0 个，失败 1 个` |
| 对话框弹出来一片空白 | 忘了 `ui->setupUi(this)` | 每个用 `.ui` 的类，构造函数第一句必须是它 |
| `windeployqt` 报 “does not seem to be a Qt executable” | 传的 exe 不是 Qt 程序，或路径写错 | 确认传的是 `release\Second-handTradingPlatform.exe` |
| Release 版闪一下就退 | 没有调试输出，看不到错 | 在 `main` 最前面加个弹框，或看 `DbManager::init` 的错误信息 |

## 收尾 · 第 3~4 周的提交

```bash
git add .
git commit -m "docs:补全第 0 周施工步骤的代码讲解"
```

打包产物**不要提交**（`release/` 在 `.gitignore` 里），把它单独拷给老师，或者发网盘链接。仓库里只放源码和文档。

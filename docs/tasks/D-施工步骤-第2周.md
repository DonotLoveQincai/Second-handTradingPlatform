## 第 6 步 · `buildServices()`：全项目唯一 new 对象的地方

### 这一步在干什么

程序里有一堆对象：4 个 DAO（管数据库读写）、4 个 Service（管业务规则）、5 个页面（管显示）。它们之间要互相调用，谁负责造它们？

**答案是你，`MainWindow`。** 而且只在这一个函数里造。这就是“界面类主导其他类”最实在的落地：别的类都是被主窗口造出来的，主窗口不给谁指针，谁就用不了数据库。

### 6.1 在 `mainwindow.h` 里加前置声明和成员

先加前置声明（放在 `#include` 下面、`class MainWindow` 上面）：

```cpp
class IUserRepository;   class IProductRepository;
class IOrderRepository;  class ITradeLogRepository;
class AuthService;  class ProductService;  class OrderService;  class TradeService;
class ImportService;
class SearchPage;   class MyProductsPage;  class MyOrdersPage;
class TradeLogPage; class ImportPage;
```

再加成员（放在 `private:` 段里）。**但先加一句函数声明** —— 这一句漏了，`mainwindow.cpp` 里一调就是 `C2039: "buildServices": 不是 "MainWindow" 的成员`：

```cpp
private:
    void buildServices();  // 建 4 个 DAO + 4 个 Service，全项目唯一 new 的地方
    void buildUi();        // 建导航项、放页面
    void connectBus();     // 全项目唯一 connect 的地方（第 2 周填满）
```

然后再加成员：

```cpp
private:
    // 四个 DAO / 五个 Service，全部由 MainWindow 持有
    IUserRepository*    m_userRepo    = nullptr;
    IProductRepository* m_productRepo = nullptr;
    IOrderRepository*   m_orderRepo   = nullptr;
    ITradeLogRepository* m_logRepo    = nullptr;

    AuthService*    m_authService    = nullptr;
    ProductService* m_productService = nullptr;
    OrderService*   m_orderService   = nullptr;
    TradeService*   m_tradeService   = nullptr;
    ImportService*  m_importService  = nullptr;   // 第 11 步用

    // 五个页面
    SearchPage*     m_searchPage     = nullptr;
    MyProductsPage* m_myProductsPage = nullptr;
    MyOrdersPage*   m_myOrdersPage   = nullptr;
    TradeLogPage*   m_tradeLogPage   = nullptr;
    ImportPage*     m_importPage     = nullptr;
```

**逐段讲解**

| 片段 | 作用 |
| --- | --- |
| `class IUserRepository;` | **前置声明**，只告诉编译器“有这么个类型”，不说它长什么样。因为这里只用到它的**指针**，指针大小固定，不需要完整定义 |
| `IProductRepository*` | 类型名以 `I` 开头，`I` 就是 interface（接口）的缩写。它是个只声明函数、没有成员的抽象类，随便哪个 DAO 都能“实现”它 |
| `m_userRepo` | `m_` 前缀是成员变量（member）的约定，看到就知道是“这个类自己的字段”，不是局部变量或参数 |
| `AuthService*` | 服务类的指针。服务类是实现业务规则的，比如“密码错三次该提示什么” |
| `= nullptr` | 默认值。主窗口构造出来时这些指针全是空的，谁忘了赋值，后面一用就崩在明确的地方，比指向随机地址好查得多 |
| `SearchPage* m_searchPage` | 页面类指针。页面本身是 `QWidget`，要显示在界面上，所以主窗口必须拿着它 |

**为什么不能写成值成员**（`AuthService m_authService;`）

两个原因。第一，这些类的构造函数都要参数（Service 要拿 DAO 指针），值成员没法在不知道参数的情况下构造。第二，`QObject` 及其子类**禁止拷贝**，值成员在拷贝主窗口时会出错。

所以只能写成指针，`new` 出来。**Service 和页面**的父对象传 `this`，让 Qt 的对象树负责销毁；**四个 DAO 不是 `QObject`**，没有父对象这回事，得自己在析构函数里 `delete`（见 6.2）。

### 6.2 实现 `buildServices()`

在 `mainwindow.cpp` 顶部加 include：

```cpp
#include "data/user_dao.h"
#include "data/product_dao.h"
#include "data/order_dao.h"
#include "data/trade_log_dao.h"
#include "services/auth_service.h"
#include "services/product_service.h"
#include "services/order_service.h"
#include "services/trade_service.h"
```

函数本体：

```cpp
void MainWindow::buildServices()
{
    // 顺序不能错：先 DAO，再 Service（Service 构造要拿到 DAO 指针）
    // 注意：四个 DAO 都没有继承 QObject，构造函数不接 parent，所以这里不能传 this
    m_userRepo    = new UserDao();
    m_productRepo = new ProductDao();
    m_orderRepo   = new OrderDao();
    m_logRepo     = new TradeLogDao();

    m_authService    = new AuthService(m_userRepo, this);
    m_productService = new ProductService(m_productRepo, this);
    m_orderService   = new OrderService(m_orderRepo, m_productRepo, m_logRepo, this);
    m_tradeService   = new TradeService(m_orderRepo, m_productRepo, m_logRepo, this);
}
```

DAO 不是 `QObject`，没有对象树帮你收尸，所以在析构函数里手动删（Service 和页面是 `QObject`，parent 是 `this`，Qt 会自己删，**不要**再写 delete）：

```cpp
MainWindow::~MainWindow()
{
    // Service 和页面都是 QObject，parent = this，Qt 会自己删；
    // 四个 DAO 不是 QObject，得在这里手动删
    delete m_tradeService;   m_tradeService = nullptr;
    delete m_orderService;   m_orderService = nullptr;
    delete m_productService; m_productService = nullptr;
    delete m_authService;    m_authService = nullptr;

    delete m_logRepo;     m_logRepo = nullptr;
    delete m_orderRepo;   m_orderRepo = nullptr;
    delete m_productRepo; m_productRepo = nullptr;
    delete m_userRepo;    m_userRepo = nullptr;

    delete ui;
}
```

**逐段讲解**

| 片段 | 作用 |
| --- | --- |
| `new UserDao()` | 在堆上造一个 DAO 对象。DAO 是纯 C++ 类（只继承 `IUserRepository`），**不是 `QObject`**，所以没有 `parent` 参数 |
| `this` 作为 parent（Service、页面用） | 把对象挂到主窗口的 Qt 对象树上。主窗口销毁时，所有子对象自动跟着销毁，你**不用写 delete** |
| `delete m_tradeService` 先删 Service | 先把用 DAO 的对象删掉，再删 DAO，避免“服务还活着但它的 DAO 没了” |
| `m_userRepo = nullptr` | 删完置空，防止以后手滑再 `delete` 一次（重复 delete 会崩） |
| `m_userRepo = new UserDao()` | 把它赋给成员。注意左边类型是接口指针 `IUserRepository*`，右边是具体实现 `UserDao*`，这叫向上转型，因为 `UserDao` 继承了 `IUserRepository` |
| `new AuthService(m_userRepo, this)` | Service 构造时拿到 DAO 的指针，之后 Service 内部调 `m_userRepo->findByUsername(...)` 就能查库 |
| `new OrderService(m_orderRepo, m_productRepo, m_logRepo, this)` | 下单 Service 要三个 DAO。为什么三个？因为它要在**一个事务里**改三张表：写订单、把商品标成已售出、写一条状态日志 |
| `new TradeService(...)` | 改状态的 Service，要的也是这三个，理由同上（取消订单要把商品放回在售） |

**⚠️ 两条铁律**

1. **构造参数顺序必须和 `docs/01-契约.md` §7.2 完全一致**。差一个顺序，C++ 可能编译通过但行为诡异（两个都是指针时类型不同才会报错，同类型就直接静默错位）。
2. **全项目只有这个函数里出现 `new XxxDao` 和 `new XxxService`**。A、B、C 的页面里都**不许** `new` 数据库对象。他们说“我需要查数据”时，正确做法是构造函数收一个 Service 指针，不是自己 new。

### 6.3 在构造函数里调用

```cpp
MainWindow::MainWindow(QWidget* parent)
    : QMainWindow(parent)
    , ui(new Ui::MainWindow)
{
    ui->setupUi(this);

    setWindowTitle(QStringLiteral("二手交易平台"));
    resize(1100, 700);

    buildServices();     // 先把对象造好
    buildUi();           // 再造页面（页面构造需要 Service 指针）
    connectBus();        // 最后接线

    statusBar()->showMessage(QStringLiteral("数据库：") + DbManager::dbPath());
}
```

`buildServices()` 必须在最前面。`buildUi()` 里要 `new ImportPage(m_productService, this)`，如果 Service 还没造出来，传进去的就是空指针。

### 6.4 名字的含义

`buildServices` 读作“构建服务层”。名字里 `build` 是“组装、搭建”的意思，`Services` 是复数，指整个服务层（四个 Service）。**函数名要说清“造什么”，不要叫 `init2()` 或者 `setup()`**，`setup` 太模糊，看不出造的是对象还是配置。

同理你这周还会写 `buildUi()`（造界面）、`connectBus()`（接线）。三个 `build/connect` 开头的函数各自负责一层，看名字就知道该去哪改。

### 6.5 验证

编译。这时候报错是正常的，因为 A、B、C 的类可能还没合进来。按这个顺序处理：

| 报错 | 意思 | 怎么办 |
| --- | --- | --- |
| `C2039: "buildServices": 不是 "MainWindow" 的成员` | `mainwindow.cpp` 里调了/定义了它，但 `mainwindow.h` 的 `private:` 段里没声明 | 在头文件 `private:` 下补一行 `void buildServices();`（6.1 那句，最容易漏） |
| `C2665: "UserDao::UserDao": 没有重载函数可以转换所有参数类型` | DAO 不是 `QObject`，构造函数没有 `parent` 参数，`new UserDao(this)` 传不进去 | 改成 `new UserDao();`（四个 DAO 都不传 `this`），并且去析构函数里手动 delete |
| `C1083: 无法打开包括文件 "data/user_dao.h"` | 文件不存在 | 去 `git log --all` 看 B 的分支有没有这个文件，没有就是还没写 |
| `C2027: 使用了未定义类型` | 只前置声明了，但用到了对象本身 | 检查是不是不小心写了 `IUserRepository repo;` 这种值类型 |
| `C2664: 无法将参数 1 从 X 转换为 Y` | 构造参数类型不对 | 对照契约 §7.2 改 |
| `LNK2019: 无法解析的外部符号` | 函数声明了但没有实现 | 重新生成工程（新 `.cpp` 没进工程），或者对方还没写实现 |

## 第 7 步 · 把占位页换成真页面

### 这一步在干什么

第 0 周 `buildUi()` 里是五个 `makePlaceholder(...)`，现在换成真页面对象。

### 7.1 改 `buildUi()`

**先看清一件事：第 7 步不是一次接完五个页面。** 五个页面分属四个人，合进 `develop` 的时间不一样（B 的「我的订单」、你的「批量导入」都还没写）。所以这一步分两小步：

- **7.1A 现在能接的三个**（`SearchPage`、`MyProductsPage`、`TradeLogPage` —— A 和 C 已经合进 `develop` 了）；
- **7.1B 剩下两个**（`MyOrdersPage` 等 B 写完；`ImportPage` 是你第 11 步自己写）——它们的位置先放占位页，凑满五项导航。

先接三个：

```cpp
void MainWindow::buildUi()
{
    // 0) 先清掉 Designer 里残留的空页。第 0 周在 Qt Designer 里拖 QStackedWidget 时，
    //    它自带 page / page_2 两个空 QWidget。不清掉的话，代码 addWidget 的五个页面
    //    会整体后移两位 —— 点「批量导入」看到的是「我的订单」的占位页。
    while (ui->stackedWidget->count() > 0) {
        QWidget* w = ui->stackedWidget->widget(0);
        ui->stackedWidget->removeWidget(w);
        delete w;
    }

    // 1) 造页面。现在 develop 里只有这三个页面类，先接这三个：
    //    m_myOrdersPage（B 的，还没写）和 m_importPage（第 11 步才写）先用占位页占位置，
    //    等它们的类进了 develop，再把 makePlaceholder 换成 new XxxPage(...)。
    m_searchPage     = new SearchPage(m_productService, this);
    m_myProductsPage = new MyProductsPage(m_productService, this);
    m_tradeLogPage   = new TradeLogPage(m_tradeService, this);

    // 2) 按导航顺序放进 QStackedWidget（顺序必须和下面 addItem 一致！）
    ui->stackedWidget->addWidget(m_searchPage);
    ui->stackedWidget->addWidget(m_myProductsPage);
    ui->stackedWidget->addWidget(makePlaceholder(QStringLiteral("我的订单")));
    ui->stackedWidget->addWidget(m_tradeLogPage);
    ui->stackedWidget->addWidget(makePlaceholder(QStringLiteral("批量导入")));

    ui->navList->addItem(QStringLiteral("商品检索"));
    ui->navList->addItem(QStringLiteral("我的商品"));
    ui->navList->addItem(QStringLiteral("我的订单"));
    ui->navList->addItem(QStringLiteral("交易记录"));
    ui->navList->addItem(QStringLiteral("批量导入"));

    ui->navList->setCurrentRow(0);
    ui->stackedWidget->setCurrentIndex(0);

    connect(ui->navList, &QListWidget::currentRowChanged,
            ui->stackedWidget, &QStackedWidget::setCurrentIndex);
}
```

> **第 0 条循环为什么要写**：`QStackedWidget` 的页码就是 `addWidget` 的先后顺序。`.ui` 里
> 只要多一个空页，代码加的所有页面都往后错一位，而且**不报错**——现象就是"点某个导航，右边
> 显示的是另一个页面的内容"。也可以在 Designer 里把 `page`/`page_2` 删掉，但代码里兜一道，
> 别人改动 `.ui` 也不会再错位。

`mainwindow.cpp` 顶部补三个 include（页面类必须 include 完整定义，前置声明不够 —— 这里要 `new`，编译器得知道大小和构造函数）：

```cpp
#include "ui/pages/product/search_page.h"
#include "ui/pages/product/my_products_page.h"
#include "ui/pages/trade/trade_log_page.h"
```

**7.1B 等页面齐了之后再改成最终版**（`MyOrdersPage` 由 B 提供，构造参数以 `docs/tasks/B-用户与订单域.md` 为准；`ImportPage` 见第 11 步，它收的是 **`ImportService*`**，不是 `ProductService*`）：

```cpp
    m_myOrdersPage   = new MyOrdersPage(/*按 B 的文档传参，见 B-用户与订单域.md*/, this);
    m_importPage     = new ImportPage(m_importService, this);
```

然后 `addWidget` 里两处 `makePlaceholder(...)` 换成 `addWidget(m_myOrdersPage)` / `addWidget(m_importPage)`。

**逐段讲解**

| 片段 | 作用 |
| --- | --- |
| `new SearchPage(m_productService, this)` | 页面构造要参数：第一个是它要用的 Service（检索页要查商品），第二个是父对象。**签名以各人任务文档为准**，不是统一 `(this)` |
| `new ImportPage(m_productService, this)` | 导入页只需要商品 Service（它只往库里加商品） |
| `addWidget(page)` | 往 `QStackedWidget` 里塞一页。塞进去的页默认不显示，靠 `setCurrentIndex` 切换 |
| `addItem(文字)` | 往左边导航列表里加一项。**这一项和上面那一页是靠序号对应的**，不是靠名字 |
| `setCurrentRow(0)` | 默认选中第 0 项（第一项） |
| `setCurrentIndex(0)` | 默认显示第 0 页 |
| `connect(navList, currentRowChanged, stackedWidget, setCurrentIndex)` | 导航选中行变了，右侧就切到同一序号的页 |

**⚠️ 踩坑率最高的一处**

`addWidget` 的顺序必须和 `addItem` 的顺序**一模一样**。两者的对应关系只有“谁先谁后”，Qt 不做任何名字匹配。

如果你先 `addWidget(importPage)` 再 `addWidget(searchPage)`，但 `addItem` 里“商品检索”排第一，结果就是点“商品检索”出来导入页。这种错**不报任何错误**，只能靠眼睛看，而且答辩演示时特别丢人——所以改完一定要逐项点一遍。

### 7.2 页面之间不许互相 include

页面 A 想跳转到页面 B，比如检索页双击商品后想打开订单页，**不要** `#include "my_orders_page.h"` 然后调对方的方法。正确做法是发信号，由主窗口转发。

理由：页面之间直接引用，改一个页面就会牵连另一个，最后变成一团。你们的契约里写了“跨模块只走 `core/` 接口 + 信号槽”，就是防这个。

### 7.3 验证

- 点五个导航：前三个是真页面（商品检索、我的商品、交易记录），后两个还是占位页（等 B 的订单页、你第 11 步的导入页）——**这是正常的**，不要为了“五个都是真页面”去等别人
- 每个页面都不崩（不崩说明页面构造函数本身没问题，也说明 Service 指针传对了）
- 点第 N 项导航，右边**必须**是第 N 个页面。点「批量导入」却显示「我的订单」，说明 `.ui` 的 `QStackedWidget` 里多了空页（见 7.1 第 0 条那个循环）
- 页面里的按钮点了没反应是正常的：第 8 步之前没人接线

| 报错 | 意思 | 怎么办 |
| --- | --- | --- |
| `C2665: "SearchPage::SearchPage": 没有重载函数可以转换所有参数类型` | 页面构造要先收 Service 指针，你只传了 `this` | 按各人任务文档的签名写：`new SearchPage(m_productService, this)` |
| `C2027: 使用了未定义类型 "MyOrdersPage"` / `C3861: 找不到标识符` | 这个页面类还没进 `develop` | 用 `makePlaceholder` 占位，等 B 合进来再接 |
| `C2065: "m_importPage": 未声明的标识符` | 头文件里的成员没加全 | 回 6.1 对照一遍成员声明 |
| `error C2601: "xxx": 本地函数定义非法` 或大括号数量报错 | 粘贴代码时多了一个 `}` 或少了 `}` | 数大括号：`buildUi` 一对，`connectBus` 一对，别把两个函数的结尾粘成一串 |

## 第 8 步 · `connectBus()`：全项目唯一 connect 的地方

### 这一步在干什么

页面把用户操作变成信号发出去，Serve 层把数据变化变成信号发出来。这些信号要有人收。**全部由主窗口收，全部写在这一个函数里。**

这样做的意义：想知道“点下单以后程序做了什么”，只需要看这一个函数，不用在全项目里搜 `connect`。

### 8.1 实现

```cpp
void MainWindow::connectBus()
{
    // 页面 → 主窗口：检索页双击商品，交给主窗口去弹购买框
    connect(m_searchPage, &SearchPage::buyRequested,
            this, &MainWindow::onBuyRequested);

    // 服务 → 主窗口：任何数据变了，让三个列表页各重查一次
    connect(m_productService, &ProductService::productsChanged,
            this, &MainWindow::onDataChanged);
    connect(m_tradeService, &TradeService::orderStatusChanged,
            this, &MainWindow::onDataChanged);
    connect(m_orderService, &OrderService::orderCreated,
            this, &MainWindow::onDataChanged);

    // 登录状态变化
    connect(m_authService, &AuthService::loginSucceeded,
            this, &MainWindow::onLoginChanged);
    connect(m_authService, &AuthService::logoutDone,
            this, &MainWindow::onLoginChanged);
}
```

**逐段讲解**

| 片段 | 作用 |
| --- | --- |
| `connect(发送者, &类::信号, 接收者, &类::槽)` | 建立一条“信号发出时自动调用槽”的连接。四个参数，前两个是一对，后两个是一对 |
| `&SearchPage::buyRequested` | 信号函数的地址。信号只有声明，没有实现，实现是 moc 自动生成的 |
| `this, &MainWindow::onBuyRequested` | 信号来了调用主窗口的这个成员函数 |
| 为什么是 `onXxx` 命名 | `on` 前缀 + 动作名，是槽函数的通用命名法，“响应某事件的方法” |
| `productsChanged` | 商品数据变了（上架、下架、改信息）。不带参数的信号，接收方收到后自己重查 |
| `orderCreated(int)` | 带一个参数（订单 id）。这里故意连到一个**不带参数**的槽，Qt 允许信号参数多于槽参数（多余的丢掉） |
| `loginSucceeded` / `logoutDone` | 登录成功 / 退出登录。两者都连到同一个槽，因为处理逻辑一样（刷新界面上的用户名） |

**Qt 的 connect 为什么允许参数个数不同**

信号 `orderCreated(int orderId)` 发出时带一个 int，槽 `onDataChanged()` 不要参数，Qt 编译期就允许，运行时直接忽略那个 int。反过来的（槽要参数、信号没有）编译就报错。

这个特性有用：`onDataChanged()` 不需要知道是哪个订单变了，它只需要知道“有东西变了，去重查”。

### 8.2 三个槽函数的实现

```cpp
void MainWindow::onDataChanged()
{
    // 不做增量刷新：谁的数据可能变了就整页重查一次，几十条数据无感
    if (m_searchPage)     m_searchPage->refresh();
    if (m_myProductsPage) m_myProductsPage->refresh();
    if (m_myOrdersPage)   m_myOrdersPage->refresh();
}

void MainWindow::onBuyRequested(int productId)
{
    if (!Session::instance().isLoggedIn()) {
        QMessageBox::information(this, QStringLiteral("提示"),
                                 QStringLiteral("请先登录"));
        return;
    }
    BuyDialog dlg(productId, this);      // B 的对话框
    if (dlg.exec() == QDialog::Accepted)
        statusBar()->showMessage(QStringLiteral("下单成功"), 3000);
}

void MainWindow::onLoginChanged()
{
    if (Session::instance().isLoggedIn())
        setWindowTitle(QStringLiteral("二手交易平台 - %1")
                           .arg(Session::instance().currentUser().nickname));
    else
        setWindowTitle(QStringLiteral("二手交易平台"));
}
```

**逐段讲解**

| 片段 | 作用 |
| --- | --- |
| `if (m_searchPage)` | 空指针检查。防御性写法：万一哪个页面没造出来，这里跳过而不是崩 |
| `refresh()` | 页面自己提供的公开槽，“重新查一遍数据并刷新界面”。每个页面都必须有，契约里规定了 |
| `Session::instance()` | 单例，全局唯一的“当前登录状态”。`instance()` 返回那个唯一的对象 |
| `isLoggedIn()` | 问它“现在有人登录吗” |
| `Session::instance().currentUser()` | 拿到当前登录的 `User` 结构体（含 id、username、nickname） |
| `BuyDialog dlg(productId, this);` | **栈上**造的对话框，函数结束自动销毁。对话框是短命的，不需要 `new` |
| `dlg.exec()` | 以**模态**方式显示：弹出来以后，用户不关它就不能操作主窗口。返回值表示用户是确定还是取消 |
| `QDialog::Accepted` | 用户点了“确定”（或等价按钮）。另一个值是 `QDialog::Rejected` |
| `statusBar()->showMessage(文字, 3000)` | 状态栏显示 3 秒后自动消失。比弹框轻，适合“下单成功”这种不需要用户确认的提示 |
| `.arg(...)` | 填 `%1` 占位符 |

**为什么 `onDataChanged` 是整页重查**

正确的做法是“哪个数据变了就只更新那一行”。但那要维护一堆索引和 diff 逻辑，几十条数据的规模下，整页重查的耗时可忽略（毫秒级），代码却简单十倍。

这是这个项目里少数几个**故意选简单方案**的地方，答辩被问到就这么答：“数据量在几十到几百条，重查的代价远小于维护增量更新带来的 bug 风险。”

### 8.3 `mainwindow.h` 里要补的声明

```cpp
private slots:
    void onDataChanged();
    void onBuyRequested(int productId);
    void onLoginChanged();
```

| 片段 | 作用 |
| --- | --- |
| `private slots:` | Qt 的关键字（其实是宏），标记下面的是槽函数。能被 `connect` 连的**成员函数**必须写在 `slots:` 段里，或者至少是普通成员函数也能连（Qt5 新语法下不强制），但写在里面语义清楚 |
| `private` 而不是 `public` | 槽只给信号调用，不给外面直接调，所以私有 |

1. 双击检索页的一个商品 → 弹出 B 的购买确认框（如果 B 的 `BuyDialog` 已经合进来）
2. 在购买框里点确定 → 状态栏出现“下单成功”，订单列表里多一条

## 第 9 步 · 登录流程接进 `main.cpp`

### 这一步在干什么

现在程序一启动就直接进主窗口。要改成：先弹登录框，登录成功才进主窗口。

### 9.1 改 `main.cpp`

顶部加 include：

```cpp
#include "core/session.h"
#include "services/auth_service.h"
#include "data/user_dao.h"
#include "ui/pages/auth/login_dialog.h"
```

`main` 函数里，在数据库初始化之后、主窗口之前插入：

```cpp
    // 3) 先弹登录框；用户点 X 直接退出，不要进到一个没登录的主界面
    UserDao userDao;
    AuthService authService(&userDao);
    LoginDialog loginDlg(&authService);
    if (loginDlg.exec() != QDialog::Accepted)
        return 0;

    MainWindow w;
    w.setCurrentUser(Session::instance().currentUser());   // 标题栏显示 alice
    w.show();
```

**逐段讲解**

| 片段 | 作用 |
| --- | --- |
| `UserDao userDao;` | 栈上造 DAO，没有父对象。它在 `main` 结束前一直活着 |
| `AuthService authService(&userDao);` | 把 DAO 的地址交给 Service。`&userDao` 取地址，因为 Service 构造要的是指针 |
| `LoginDialog loginDlg(&authService);` | 登录框只需要认证 Service，不需要直接碰数据库 |
| `loginDlg.exec() != QDialog::Accepted` | 用户点了关闭（X）或者“取消”，就 `return 0` 直接退出程序。**不能**继续往下建主窗口 |
| `w.setCurrentUser(...)` | 把登录后的用户告诉主窗口，标题栏显示昵称 |
| `Session::instance()` | 登录成功时 `AuthService::login` 已经把用户存进单例了，这里取出来用 |

**为什么这里是栈对象，主窗口里是 `new`**

`main` 里这两个对象生命周期和 `main` 一样长，栈上就够，函数结束自动析构，不用管。

主窗口里那一套必须 `new`，因为要挂到 Qt 对象树上，而且要活过很多个函数调用。

**两处并存不冲突**：`DbManager::db()` 返回的是同一条连接，`UserDao` 造几个都行，都往同一条连接上发查询。

### 9.2 `LoginDialog` 是谁的

B 的。你只需要知道两件事：

- 构造参数是 `AuthService*`
- `exec()` 返回 `QDialog::Accepted` 表示登录成功

**对话框不应该自己 `new`**，栈上造、`exec()` 显示、结束就销毁，这是 Qt 里对话框的标准用法。

- 启动程序 → 先弹登录框
- 输入 `alice` / `123456` → 进入主窗口，标题栏有 `Alice`
- 输错密码 → 弹提示，仍停在登录框
- 点登录框的 X → 程序直接退出，不出现主窗口

## 第 10 步 · 演示数据（`工具 → 重置演示数据`）

### 这一步在干什么

答辩前需要一段“数据刚好摆好”的状态：几个账号、十几件商品、一单正在进行的订单。手动点出来太慢，还要保证每次演示前都能一键恢复到同一状态。

所以做一个菜单项，点一下就把演示数据补齐。

### 10.1 加菜单

打开 `ui/mainwindow.ui`，在菜单栏上加：`工具` → `重置演示数据`。

**槽名必须叫 `onResetDemoData()`**，这是 Qt 的自动连接规则：菜单项 `objectName` 是 `actionResetDemoData` 时，Qt 会自动把它连到同名风格的槽 `on_actionResetDemoData_triggered()`；我们用自己手动连的 `onResetDemoData()`，在 `buildUi()` 或 `connectBus()` 里补一句：

```cpp
connect(ui->actionResetDemoData, &QAction::triggered,
        this, &MainWindow::onResetDemoData);
```

**为什么要用 `UserDao::insert` 而不能直接写 SQL 插用户**

因为密码要加盐哈希。`UserDao::insert` 收到明文 `passwordHash` 字段后，内部自己生成盐、算哈希、写库。如果你手写 SQL 插一个假哈希，登录永远失败，而且很难看出原因。

**演示数据的密码就写明文 `"123456"` 赋值给 `user.passwordHash`**，这不是漏洞，是刻意让 DAO 走“明文进、哈希出”的流程，答辩被问就这么解释。

### 10.2 实现 `onResetDemoData()`

```cpp
void MainWindow::onResetDemoData()
{
    if (QMessageBox::question(this, QStringLiteral("重置演示数据"),
            QStringLiteral("会补充演示账号、商品和一单示例订单，已有的不会重复。继续？"))
        != QMessageBox::Yes)
        return;

    // ---------- 1) 三个用户：走 UserDao::insert，明文密码由 DAO 内部加盐哈希 ----------
    const QVector<QPair<QString, QString>> seedUsers = {
        { QStringLiteral("alice"), QStringLiteral("Alice") },
        { QStringLiteral("bob"),   QStringLiteral("Bob")   },
        { QStringLiteral("carol"), QStringLiteral("Carol") },
    };

    QHash<QString, int> uid;
    for (const auto& u : seedUsers) {
        int id = -1;
        if (!m_userRepo->exists(u.first)) {
            User user;
            user.username     = u.first;
            user.nickname     = u.second;
            user.passwordHash = QStringLiteral("123456");   // 明文！DAO 会哈希
            auto r = m_userRepo->insert(user);
            if (!r.ok) {
                QMessageBox::warning(this, QStringLiteral("重置失败"), r.message);
                return;
            }
            id = user.id;
        } else {
            auto existing = m_userRepo->findByUsername(u.first);
            id = existing ? existing->id : -1;
        }
        uid[u.first] = id;
    }

    if (uid["alice"] <= 0 || uid["bob"] <= 0) {
        QMessageBox::warning(this, QStringLiteral("重置失败"),
                             QStringLiteral("演示账号创建失败"));
        return;
    }

    // ---------- 2) 12 件商品：直接 SQL，seller_id 用真实 id ----------
    struct Seed { const char* title; int cat; double price; int cond; const char* desc; };
    const QVector<Seed> seedProducts = {
        { "九成新 iPhone 13 128G",  6, 3200.0, 9, "国行无划痕，电池健康 92%" },
        { "Redmi K60 12+256",       6, 1450.0, 8, "自用一年，配件齐全" },
        { "二手 ThinkPad T480",     7, 2100.0, 7, "i5-8250U 16G 512G" },
        { "罗技 K380 键盘",         7,   89.0, 8, "蓝牙连接正常" },
        { "AirPods 3 港版",         8,  620.0, 8, "无明显划痕" },
        { "漫步者蓝牙耳机",          8,   85.0, 6, "音质正常，耳罩有磨损" },
        { "高等数学 第七版 上下册",   2,   25.0, 7, "有笔记，无缺页" },
        { "C++ Primer 第 5 版",      2,   45.0, 8, "几乎全新" },
        { "大学物理 教材",            2,   18.0, 6, "封面有折痕" },
        { "宜家 小书桌",              3,  120.0, 7, "自提，需自己拆装" },
        { "优衣库 羽绒服 L 码",        4,  150.0, 8, "穿过两次" },
        { "迪卡侬 瑜伽垫",            5,   35.0, 7, "用过几次，已清洁" },
    };

    QSqlDatabase& db = DbManager::db();
    if (!db.transaction()) {
        QMessageBox::warning(this, QStringLiteral("重置失败"), QStringLiteral("开启事务失败"));
        return;
    }

    int inserted = 0;
    const QStringList sellers = { "alice", "bob" };
    for (int i = 0; i < seedProducts.size(); ++i) {
        const Seed& s = seedProducts[i];
        const int sellerId = uid.value(sellers[i % sellers.size()]);

        // 用标题判重，可反复点"重置"
        QSqlQuery chk(db);
        chk.prepare("SELECT COUNT(*) FROM products WHERE title = ?");
        chk.addBindValue(QString::fromUtf8(s.title));
        chk.exec();
        if (chk.next() && chk.value(0).toInt() > 0)
            continue;

        QSqlQuery q(db);
        q.prepare("INSERT INTO products(seller_id, category_id, title, description, "
                  "price, condition_level, status) VALUES(?,?,?,?,?,?,?)");
        q.addBindValue(sellerId);
        q.addBindValue(s.cat);
        q.addBindValue(QString::fromUtf8(s.title));
        q.addBindValue(QString::fromUtf8(s.desc));
        q.addBindValue(s.price);
        q.addBindValue(s.cond);
        q.addBindValue(Const::ProductStatus::OnSale);
        if (!q.exec()) {
            db.rollback();
            QMessageBox::warning(this, QStringLiteral("重置失败"), q.lastError().text());
            return;
        }
        ++inserted;
    }

    // ---------- 3) 一单进行中的订单：bob 买了 alice 的一件（状态 PAID，带 2 条日志） ----------
    int    demoProductId = -1;

        q.exec(QStringLiteral("SELECT id, price FROM products "
                              "WHERE status = 'ON_SALE' AND seller_id = %1 "
                              "ORDER BY id LIMIT 1").arg(uid.value("alice")));
        if (q.next()) {

        }
    }

    if (demoProductId > 0 && uid.value("bob") > 0) {
        QSqlQuery exists(db);
        exists.exec("SELECT COUNT(*) FROM orders");
        const bool hasOrder = exists.next() && exists.value(0).toInt() > 0;

        if (!hasOrder) {
            // 3.1 把商品标成已售出

            up.prepare("UPDATE products SET status = 'SOLD' WHERE id = ?");
            up.addBindValue(demoProductId);
            up.exec();

                        "amount, status, remark) VALUES(?,?,?,?,?,?,?)");

            ins.addBindValue(uid.value("bob"));
            ins.addBindValue(uid.value("alice"));
            ins.addBindValue(demoPrice);
            ins.addBindValue(Const::OrderStatus::Paid);
            ins.addBindValue(QStringLiteral("演示订单"));
            if (!ins.exec()) {
                db.rollback();
                QMessageBox::warning(this, QStringLiteral("重置失败"), ins.lastError().text());
                return;
            }
            const int orderId = ins.lastInsertId().toInt();

            // 3.3 两条日志：下单、付款
            const QVector<QPair<QString, QString>> steps = {
                { QString(),                    Const::OrderStatus::PendingPay },
                { Const::OrderStatus::PendingPay, Const::OrderStatus::Paid     },
            };
            const QVector<QString> actions = { Const::TradeAction::Create, Const::TradeAction::Pay };
            const QVector<int>  operators  = { uid.value("bob"), uid.value("bob") };

            for (int i = 0; i < steps.size(); ++i) {
                QSqlQuery log(db);
                log.prepare("INSERT INTO trade_log(order_id, from_status, to_status, "
                            "action, operator_id, remark) VALUES(?,?,?,?,?,?)");
                log.addBindValue(orderId);
                log.addBindValue(steps[i].first);
                log.addBindValue(steps[i].second);
                log.addBindValue(actions[i]);
                log.addBindValue(operators[i]);
                log.addBindValue(i == 0 ? QStringLiteral("下单") : QStringLiteral("付款"));
                if (!log.exec()) {
                    db.rollback();
                    QMessageBox::warning(this, QStringLiteral("重置失败"), log.lastError().text());
                    return;
                }
            }
        }
    }

    if (!db.commit()) {
        db.rollback();
        QMessageBox::warning(this, QStringLiteral("重置失败"), QStringLiteral("提交失败"));
        return;
    }

    onDataChanged();
    QMessageBox::information(this, QStringLiteral("完成"),
                             QStringLiteral("新增商品 %1 件。记忆账号：alice / bob / carol，"
                                            "密码都是 123456").arg(inserted));
}
```

| `!= QMessageBox::Yes` | 不是“是”就 `return`，**这是防误点的第一道关**，重置是写库操作 |
| `const QVector<QPair<QString, QString>> seedUsers` | 一个“用户名+昵称”的列表。`QPair<A,B>` 是装两个值的小结构，这里第一个是用户名（登录用），第二个是昵称（显示用） |
| `QHash<QString, int> uid` | 用户名 → 数据库 id 的映射。后面插商品要 `seller_id`，用真实 id，不能用写死的 1、2、3 |
| `for (const auto& u : seedUsers)` | 范围 for 循环，`u` 依次是每个元素。`const auto&` 表示不拷贝、也不改 |
| `m_userRepo->exists(u.first)` | 先查用户名在不在。**可重复点**的关键：已存在就不重复插 |
| `user.passwordHash = "123456"` | 字段名叫 hash，但这里存的是**明文**。这是个容易误解的地方：约定是“调用方交明文，DAO 内部哈希”。字段名历史遗留，改不了，注释里写清了 |
| `auto r = m_userRepo->insert(user);` | 插入并拿到 `OpResult`。`user.id` 在成功后被 DAO 填成新 id |
| `if (!r.ok)` / `r.message` | 失败就用 DAO 给的提示弹框，不再自己编错误信息 |
| `existing ? existing->id : -1` | 三元运算符。`findByUsername` 返回的是 `std::optional<User>`，有值就取 id，没值给 -1 |
| `struct Seed { const char* title; ... }` | 定义一个只在本函数用的结构体，装一条演示商品。用 `const char*` 而不是 `QString`，是为了初始化列表写得紧凑 |
| `QString::fromUtf8(s.title)` | 把 `const char*` 转成 `QString`。源码是 UTF-8，所以用 `fromUtf8`，用 `fromLocal8Bit` 在别人机器上可能乱码 |
| `if (!db.transaction())` | 开启事务。失败说明连接有问题，直接退出 |
| `sellers[i % sellers.size()]` | 轮流分给 alice 和 bob。`%` 取余实现“0,1,0,1…”的循环 |
| `chk.prepare(...)` + `addBindValue(...)` + `exec()` | 参数化查询三步。**不要用字符串拼接 SQL**，`?` 占位符由驱动负责转义，这是防注入的基本功 |
| `continue` | 这件商品已存在（标题重复），跳过不插 |
| `db.rollback()` | 任何一步失败就回滚，前面插的东西全部撤销，不留半套数据 |
| `SELECT ... WHERE seller_id = %1".arg(...)` | 这里用 `.arg()` 拼整数是安全的（值来自我们自己的 `uid`，不是用户输入），但**只在这个场景可以**，处理用户输入时一律用 `?` |
| `q.value(1).toDouble()` | 取商品真实价格。**不能写死 3200**，因为轮到的是哪件商品由 `ORDER BY id LIMIT 1` 决定 |
| `ins.lastInsertId().toInt()` | 刚插入那行订单的 id。日志要 `order_id`，靠它拿 |
| `if (!hasOrder)` | 订单表已经有数据就不再建，保证点十次也只有一单 |
| `QDate::currentDate().toString("yyyyMMdd")` | 今天日期格式化成 `20251022`，订单号前缀 |
| `+ "-0001"` | 拼成完整订单号 `20251022-0001`。序号写死 0001，因为演示只建一单 |
| `from_status` 填 `QString()` | 第一条日志表示“从无到有”，`from_status` 空着，对应契约里“日志 `from=""`”的约定 |
| `i == 0 ? "下单" : "付款"` | 第一条备注“下单”，第二条“付款” |
| `db.commit()` | 全部成功才提交。提交失败也要 rollback，不能装作成功 |

**演示数据的三条设计原则**

1. **可重复执行**：用户按用户名判重、商品按标题判重、订单看表里有没有。点多少次结果都一样。
2. **不写死 id**：所有外键都用查询回来的真实 id。写死 id 在换台电脑重建库后必然错位。
3. **金额取真实值**：订单金额来自商品自己的 `price`，不是常量。演示时金额对不上是很容易被抓的错。

## 第 11 步 · `ImportService`：CSV 批量导入

### 这一步在干什么

老师或者演示需要一个“从文件导入商品”的功能。选一个 CSV，一次导入几十件商品。

难点不在读文件，在**校验**：格式错了要告诉用户哪一行错了，而不是默默导入半套数据。

### 11.1 定好导入规则

| 项目 | 规则 |
| --- | --- |
| 编码 | UTF-8 或 GBK 都接受（Excel 另存为 CSV 默认 GBK） |
| 第一行 | 必须是表头 `title,category,price,condition_level,description` |
| 列数 | 至少 4 列，第 5 列 description 可选 |
| 卖家 | 就是当前登录用户，CSV 里不写卖家 |
| 错误处理 | **任何一行不合法，整批一条都不导入** |

最后一条最重要。如果“对了 8 行、错 2 行”就只导 8 行，用户会以为 10 行全成功。要么全成，要么全不成，这样报错才是可信的。

```cpp
#include "core/repository/i_product_repository.h"
#include "data/db_manager.h"

namespace {

// 把一个 CSV 行切成字段，处理引号和 "" 转义
QStringList parseCsvLine(const QString& line)
{
    QStringList out;
    QString field;
    bool inQuotes = false;

    for (int i = 0; i < line.size(); ++i) {
        const QChar c = line.at(i);
        if (inQuotes) {
            if (c == QLatin1Char('"')) {
                if (i + 1 < line.size() && line.at(i + 1) == QLatin1Char('"')) {
                    field += QLatin1Char('"');    // "" → 一个引号
                    ++i;
                } else {
                    inQuotes = false;             // 引号结束
                }
            } else {
                field += c;
            }
        } else {
            if (c == QLatin1Char('"')) {
                inQuotes = true;
            } else if (c == QLatin1Char(',')) {
                out << field;
                field.clear();
            } else {
                field += c;
            }
        }
    }
    out << field;                                  // 最后一个字段
    return out;
}

// 先按 UTF-8 解，失败再按系统编码（中文 Windows = GBK）解
QString decodeBytes(const QByteArray& bytes)
{
    QStringDecoder utf8(QStringConverter::Utf8);
    QString text = utf8.decode(bytes);
    if (utf8.hasError()) {
        QStringDecoder sys(QStringConverter::System);
        text = sys.decode(bytes);
    }
    if (text.startsWith(QChar(0xFEFF)))            // 去掉 BOM
        text.remove(0, 1);
    return text;
}

// 分类名（支持"数码电子/手机"这种父/子写法）→ id，找不到返回 -1
int findCategoryId(QSqlDatabase& db, const QString& name)
{
    const QString trimmed = name.trimmed();
    if (trimmed.isEmpty())
        return -1;

    const int slash = trimmed.indexOf(QLatin1Char('/'));
    const QString child  = slash >= 0 ? trimmed.mid(slash + 1).trimmed() : trimmed;
    const QString parent = slash >= 0 ? trimmed.left(slash).trimmed() : QString();

    QSqlQuery q(db);
    if (parent.isEmpty()) {
        q.prepare("SELECT id FROM categories WHERE name = ?");
        q.addBindValue(child);
    } else {
        q.prepare("SELECT c.id FROM categories c "
                  "JOIN categories p ON p.id = c.parent_id "
                  "WHERE c.name = ? AND p.name = ?");
        q.addBindValue(child);
        q.addBindValue(parent);
    }
    if (q.exec() && q.next())
        return q.value(0).toInt();
    return -1;
}

} // namespace

ImportService::ImportService(IProductRepository* productRepo, IUserRepository* userRepo,
                             QObject* parent)
    : QObject(parent)
    , m_productRepo(productRepo)
    , m_userRepo(userRepo)
{
}

ImportReport ImportService::importCsv(const QString& filePath, int defaultSellerId)
{
    ImportReport report;

    QFile f(filePath);
    if (!f.open(QIODevice::ReadOnly)) {
        report.errors << QStringLiteral("无法打开文件：%1").arg(filePath);
        return report;
    }
    const QString text = decodeBytes(f.readAll());
    f.close();

    QStringList lines = text.split(QRegularExpression(QStringLiteral("\r\n|\n|\r")),
                                   Qt::SkipEmptyParts);
    if (lines.isEmpty()) {
        report.errors << QStringLiteral("文件是空的");
        return report;
    }

    // 第一行必须是表头
    const QStringList header = parseCsvLine(lines.first());
    QStringList expect = { "title", "category", "price", "condition_level", "description" };
    QStringList actual;
    for (const QString& h : header)
        actual << h.trimmed().toLower();
    if (actual.size() < 4 || actual.mid(0, 4) != expect.mid(0, 4)) {
        report.errors << QStringLiteral("表头不对，应该以 "
                                        "title,category,price,condition_level 开头，实际是：%1")
                             .arg(lines.first());
        return report;
    }
    const bool hasDescription = actual.size() >= 5 && actual.at(4) == QStringLiteral("description");

    // 逐行校验，全部先攒起来，不落库
    QVector<Product> rows;
    QSqlDatabase& db = DbManager::db();

    for (int i = 1; i < lines.size(); ++i) {
        const int lineNo = i + 1;
        ++report.total;
        const QStringList cols = parseCsvLine(lines.at(i));

        if (cols.size() < 4) {
            report.errors << QStringLiteral("第 %1 行：列数不足（至少 4 列）").arg(lineNo);
            continue;
        }

        const QString title = cols.at(0).trimmed();
        const QString cat   = cols.at(1).trimmed();
        const QString priceStr = cols.at(2).trimmed();
        const QString condStr  = cols.at(3).trimmed();
        const QString desc  = hasDescription && cols.size() >= 5 ? cols.at(4).trimmed() : QString();

        if (title.isEmpty()) {
            report.errors << QStringLiteral("第 %1 行：标题不能为空").arg(lineNo);
            continue;
        }
        if (title.size() > 60) {
            report.errors << QStringLiteral("第 %1 行：标题超过 60 字").arg(lineNo);
            continue;
        }

        bool priceOk = false;
        const double price = priceStr.toDouble(&priceOk);
        if (!priceOk || price <= 0) {
            report.errors << QStringLiteral("第 %1 行：价格不是有效数字（%2）").arg(lineNo).arg(priceStr);
            continue;
        }

        int cond = 9;
        if (!condStr.isEmpty()) {
            bool condOk = false;
            cond = condStr.toInt(&condOk);
            if (!condOk || cond < 1 || cond > 10) {
                report.errors << QStringLiteral("第 %1 行：成色必须是 1~10 的整数").arg(lineNo);
                continue;
            }
        }

        const int catId = findCategoryId(db, cat);
        if (catId <= 0) {
            report.errors << QStringLiteral("第 %1 行：分类\"%2\"不存在").arg(lineNo).arg(cat);
            continue;
        }

        Product p;
        p.sellerId       = defaultSellerId;
        p.categoryId     = catId;
        p.title          = title;
        p.description    = desc;
        p.price          = price;
        p.conditionLevel = cond;
        rows << p;
    }

    if (!report.errors.isEmpty()) {
        report.succeeded = 0;
        return report;                     // 有错就一条不导
    }

    // 全部合法 → 整批一个事务
    if (!db.transaction()) {
        report.errors << QStringLiteral("开启事务失败");
        return report;
    }
    for (int i = 0; i < rows.size(); ++i) {
        auto r = m_productRepo->insert(rows[i]);
        if (!r.ok) {
            db.rollback();
            report.errors << QStringLiteral("第 %1 条写入失败：%2").arg(i + 1).arg(r.message);
            report.succeeded = 0;
            return report;
        }
    }
    if (!db.commit()) {
        db.rollback();
        report.errors << QStringLiteral("提交事务失败");
        report.succeeded = 0;
        return report;
    }

    report.succeeded = rows.size();
    return report;
}
```

### 11.4 逐段讲解

**`parseCsvLine`（切分一行）**

CSV 看着简单，其实有坑：字段里可以有逗号，只要用引号包起来——

```
"九成新 iPhone, 128G",手机,3200,9
```

这一行的第一个字段里有个逗号。直接用 `split(',')` 会切成两段，全错。所以必须逐字符扫描。

| 片段 | 作用 |
| --- | --- |
| `bool inQuotes = false;` | 当前是否在引号内部。这是整个函数的唯一状态 |
| `for (int i = 0; i < line.size(); ++i)` | 逐字符扫描，用下标而不是范围 for，因为要在循环里 `++i` 跳字符 |
| `if (inQuotes)` | 引号内部：逗号是普通字符，只有引号才特殊 |
| `c == '"' && line.at(i+1) == '"'` | 连续两个引号是**转义**，表示一个真正的引号字符，`++i` 跳过第二个 |
| `inQuotes = false;` | 单个引号，引号区域结束 |
| `else if (c == ',')` | 引号外部遇到逗号 → 一个字段结束，`out << field` 收集，`field.clear()` 清空准备下一个 |
| `out << field;`（循环外） | 最后一个字段后面没有逗号，循环结束后单独收进去 |

**`decodeBytes`（判断编码）**

| 片段 | 作用 |
| --- | --- |
| `QStringDecoder utf8(QStringConverter::Utf8)` | 造一个 UTF-8 解码器 |
| `utf8.decode(bytes)` | 解码。非法字节会被替换成特殊字符，不抛异常 |
| `utf8.hasError()` | 解码过程中遇到过非法字节。合法的 UTF-8 几乎不可能让 GBK 文件通过，所以用它来判断 |
| `QStringConverter::System` | 系统编码。中文 Windows 上就是 GBK（代码页 936） |
| `QChar(0xFEFF)` | BOM（字节顺序标记）的 Unicode 码点。Excel 另存为 UTF-8 CSV 会加这个，不去掉的话第一列表头会变成 `\uFEFFtitle`，表头校验失败 |

**`findCategoryId`（分类名转 id）**

| 片段 | 作用 |
| --- | --- |
| `trimmed()` | 去掉首尾空格。Excel 里手打的单元格经常带空格 |
| `indexOf('/')` | 找斜杠位置，找不到返回 -1 |
| `slash >= 0 ? 子 : 全名` | 有斜杠就拆成“父/子”，没有就整个当分类名 |
| `mid(slash+1)` / `left(slash)` | 取斜杠右边的子分类名 / 左边的父分类名 |
| `JOIN categories p ON p.id = c.parent_id` | 自连接：把分类表和它自己连起来，`c` 是子，`p` 是父，这样能同时按父子名查 |

**`importCsv` 主流程**

| 片段 | 作用 |
| --- | --- |
| `report.errors << ...; return report;` | 早期错误直接返回，`succeeded` 保持 0 |
| `text.split(QRegularExpression("\r\n|\n|\r"), Qt::SkipEmptyParts)` | 按三种换行符切行（Windows/Linux/Mac 都兼容），空的丢掉 |
| `lines.first()` | 第一行，表头 |
| `h.trimmed().toLower()` | 表头容错：去空格、转小写，`Title` 和 `title` 都认 |
| `actual.mid(0, 4) != expect.mid(0, 4)` | 只比前四列。第 5 列 description 可有可无 |
| `hasDescription` | 有第 5 列且名字对，才去读第 5 列 |
| `++report.total` | 每处理一行就计数（含错的），所以“共 N 行”是文件真实行数 |
| `continue` | 这一行有错，记错误，继续下一行，**不 return**——要一次性把所有错都报出来 |
| `priceStr.toDouble(&priceOk)` | 转换并带回是否成功。`toDouble()` 不带参数时失败返回 0，分不清“0”和“abc” |
| `cond = 9` 默认 | 成色不填就默认 9 成新 |
| `rows << p;` | 校验通过的行先攒在内存里，**一行都不落库** |
| `if (!report.errors.isEmpty()) return report;` | 有任何错，全部丢弃。这就是“要么全成，要么全不成” |
| `db.transaction()` … `commit()` | 全部合法才开事务批量插入，中途任一失败就 `rollback()` |

```cpp
{
    if (!Session::instance().isLoggedIn()) {
        m_resultEdit->setPlainText(QStringLiteral("请先登录再导入"));
        return;
    }
    if (!m_service) {
        m_resultEdit->setPlainText(QStringLiteral("导入服务不可用"));
        return;
    }

    const ImportReport r = m_service->importCsv(m_pathEdit->text(),
                                                Session::instance().currentUser().id);

    QString out = QStringLiteral("共 %1 行，成功 %2 行\n").arg(r.total).arg(r.succeeded);
    if (!r.errors.isEmpty()) {
        out += QStringLiteral("\n错误：\n");
        for (const QString& e : r.errors)
            out += QStringLiteral("· ") + e + QLatin1Char('\n');
    }
    m_resultEdit->setPlainText(out);
}
```

**逐段讲解**

| 片段 | 作用 |
| --- | --- |
| `new QVBoxLayout(this)` | 竖直布局，并且**直接把这个页面当父对象**，布局自动铺满整个页面 |
| `auto* root = ...` | `auto` 让编译器推类型，`*` 表示是原生指针。这里推出来是 `QVBoxLayout*` |
| `new QLabel(文字, this)` | 一段静态说明文字 |
| `new QHBoxLayout()` | 水平布局，装一行（输入框 + 两个按钮）。它没有父对象，因为下面要 `addLayout` 塞进竖布局 |
| `setReadOnly(true)` | 路径框只读，用户只能通过“选择文件”按钮改它，避免手打错路径 |
| `setPlaceholderText(...)` | 输入框为空时显示的灰色提示文字 |
| `setEnabled(false)` | 按钮变灰、不可点。**没选文件前不让点“开始导入”**，比点了再报错友好 |
| `row->addWidget(m_pathEdit, 1)` | 第二个参数 `1` 是拉伸因子，表示这个控件占满剩余空间，两个按钮保持原宽度 |
| `root->addWidget(m_resultEdit, 1)` | 结果框也占满剩下的竖直空间 |
| `QFileDialog::getOpenFileName(...)` | 系统文件选择框。四个参数：父窗口、标题、起始目录、过滤器 |
| `"CSV 文件 (*.csv);;所有文件 (*.*)"` | 过滤器语法：`;;` 分隔多个选项，`*.*` 是全部文件 |
| `path.isEmpty()` | 用户点了取消，返回空字符串 → 什么都不做 |
| `setPlainText(...)` | 多行纯文本框的内容，不支持富文本（不需要） |
| `QStringLiteral("· ") + e + QLatin1Char('\n')` | 每行错误前加个圆点，末尾换行。`QLatin1Char` 比 `QString` 轻 |
| `QStringLiteral("共 %1 行，成功 %2 行\n").arg(r.total).arg(r.succeeded)` | 两次 `.arg()` 依次填 `%1`、`%2`。**顺序不能反** |

## 附 · 名词补充（第 2 周才出现的）

| 名字 | 含义 |
| --- | --- |
| 前置声明 `class X;` | 只声明类型存在，不写内容。用在“只需要指针”的地方 |
| `nullptr` | 空指针。C++11 起用它代替 `NULL` 和 `0` |
| parent（父对象） | 传给 `new` 的对象。父对象销毁时子对象自动销毁 |
| 对象树 | Qt 用父子关系自动管理内存的机制 |
| `signals:` / `slots:` | Qt 的宏，标记信号和槽。`signals` 只有声明，实现由 moc 生成 |
| moc | Meta-Object Compiler，读头文件里的 `Q_OBJECT` 生成信号槽代码的工具 |
| `exec()` | 进入事件循环。对话框用它做“模态显示”，主窗口用它开整个程序 |
| 模态 | 弹窗不关，父窗口不能操作 |
| `QDialog::Accepted` | `exec()` 的返回值，表示用户确认 |
| 事务 | 一组操作，要么全成功要么全撤销。`transaction()` / `commit()` / `rollback()` |
| `lastInsertId()` | 刚插入那行的自增 id |
| 参数绑定 | 用 `?` 占位符 + `addBindValue` 填值，而不是拼字符串 |
| BOM | 文件开头的隐形标记 `EF BB BF`，UTF-8 CSV 常见，要剥掉 |
| GBK | 中文 Windows 的默认编码，Excel 另存 CSV 默认用它 |
| 自连接 | 一张表 JOIN 它自己，这里用于“子分类 + 父分类”同时匹配 |
| `OpResult` | 全项目统一的返回值：`ok` + `message` + `value` |
